Devo — App Map & Verification Architecture

Evidence-First Coding Assistant

A deterministic proof-of-concept developer tool that enforces empirical test execution over AI model claims.

The Core Journey (Execution Lifecycle)

The central invariant of Devo: The AI model's prose never influences the verdict. Only the test harness determines whether code passed, regressed, or was manipulated.

Reference Code Route (3 Key Stops)

Stop 1: The Subprocess Runner & Security Sandbox
src/devo/runner/run_check.py & src/devo/runner/parse_junit.py

Runs pytest in an isolated subprocess with stripped environment variables (preventing API token leakage), caps output to 500KB to prevent memory exhaustion, and parses XML using defusedxml to prevent XML entity expansion attacks.

Stop 2: The Workspace Boundary & Diff Protection
src/devo/workspace/boundary.py & src/devo/workspace/edits.py

Enforces path confinement within the project workspace, flags test file edits with explicit caution banners, and creates byte-for-byte pre-run snapshots enabling zero-risk rollback with devo revert.

Stop 3: The Pure-Function Verdict Engine
src/devo/verdict/compute_verdict.py

The mathematical heart of Devo. Pure Python function taking (baseline, final, confirmed_min) and producing:

  • [VERIFIED]: red_to_green or no_regression_only
  • [FAILED]: Test failures recorded or non-zero exit
  • [NOT_VERIFIED]: Timeouts, crashes, or test count regressions (catching deleted tests)

To Change This, Start Here

  • Add a new check preset (e.g. npm test or cargo test): Edit src/devo/runner/presets.py to add preset command definitions and timeout boundaries.
  • Support another LLM provider: Edit src/devo/model/api.py inside detect_api_credentials() to register endpoint and model credentials.
  • Customize terminal reporting: Edit src/devo/report/render.py to format banners, diff views, and verdict reports.

A Practice to Reuse

Deterministic Verification over Agent Prose: In any agentic development pipeline, never parse phrases like "I have fixed the issue" as evidence of completion. Build a separate, read-only harness that runs your mechanical tests and compares execution metrics (test counts, duration, exit codes) directly.

How to Run Devo

# Health check
pytest tests/

# Replay deterministic mock scenario
python -m devo run --workspace demo/workspace --task "Fix divide" --backend mock --scenario scenario_verified

# Live LLM run (auto-detects Groq or Gemini)
python -m devo run --workspace demo/workspace_api --task "Fix title_case" --backend api

# Instant rollback
python -m devo revert --run <RUN_ID> --workspace demo/workspace
